# Free Fire MAX Scoreboard

Responsive public Free Fire MAX scoreboard with an admin-only control room. Built with HTML, CSS, JavaScript and Supabase (PostgreSQL + Auth), ready to deploy on Vercel.

## Features
- Public scoreboard with no user login; live refresh every 15 seconds.
- Team roster grouped by A, B, C, etc. Contact details are never queried by public mode.
- Admin login through Supabase Auth.
- Admin can create groups, add/edit/delete teams and manage private contact details.
- Multiple events (Online Qualifiers, Semi Finals, Grand Finals, custom stages).
- Multiple map-named matches inside each event.
- Match-by-match results and cumulative event leaderboard.
- Placement points from the supplied rules: 1st 12, 2nd 9, 3rd 8, 4th 7, 5th 6, 6th 5, 7th 4, 8th 3, 9th 2, 10th 1, 11th–12th 0.
- Each kill = 1 point. Total = placement points + kills.
- Responsive layout for mobile, tablet and laptop.

## 1. Set up Supabase
1. Create a project at Supabase.
2. Open **SQL Editor**, paste all of `supabase-schema.sql`, and run it.
3. In **Authentication → Users**, create an administrator account (email/password).
4. Copy the user's UUID from Authentication → Users.
5. In SQL Editor run, replacing the placeholder with the real UUID:
   ```sql
   insert into public.admin_users (user_id)
   values ('YOUR_AUTH_USER_UUID');
   ```
6. Open **Project Settings → API** and copy the Project URL and anon/public key.

## 2. Connect the website
Open `app.js` and replace:
```js
const SUPABASE_URL = "YOUR_SUPABASE_URL";
const SUPABASE_ANON_KEY = "YOUR_SUPABASE_ANON_KEY";
```
with your project's URL and anon/public key. The anon key is intended for browser use; **never put a service-role key in frontend code**.

## 3. Run locally
Use VS Code Live Server, or from the project directory run:
```bash
python3 -m http.server 5500
```
Then open `http://localhost:5500`.

## 4. Deploy on Vercel
1. Push these files to a GitHub repository.
2. Import that repository in Vercel and deploy as a static site.
3. In Supabase Auth settings, set the Site URL to your deployed Vercel URL and add your local and deployed URLs to the allowed Redirect URLs if needed.

## Important security notes
- Public users can read only public tournament data.
- Contact details are stored in `team_contacts`, a separate table with admin-only RLS. The public app does not request this table.
- Admin authorization is not based only on a hidden button: database write policies verify membership in `admin_users`.
- Never share the Supabase service-role key.
- Only create trusted admin accounts. A Supabase Auth account that is not in `admin_users` will not have admin database permissions.

## Score calculation
Placement points are generated by PostgreSQL, not trusted from browser input. `match_results` prevents duplicate placement and duplicate team entries for the same match. The app calculates the preview; the database-generated points remain authoritative.


## Free Fire MAX scoring note
This version uses the supplied Free Fire MAX rules: 1st 12, 2nd 9, 3rd 8, 4th 7, 5th 6, 6th 5, 7th 4, 8th 3, 9th 2, 10th 1, 11th–12th 0; each elimination is 1 point. The first-place finish count is labelled BOOYAH. Use a separate Supabase project for Free Fire MAX if your existing database was already initialized for BGMI, because `CREATE TABLE IF NOT EXISTS` does not change the existing table constraints or generated scoring expressions.
